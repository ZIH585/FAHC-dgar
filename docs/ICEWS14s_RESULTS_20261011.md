## 3. 这次消融回答了什么

纯 risk 的目的，是检查去掉覆盖项能否挽回选择效果。本次结果没有支持这一点：

1. 当前纯风险选择弱于随机回放，未显示遗忘感知选择带来的收益。
2. 组合比纯 risk 好，方向上与覆盖项缓解选择集中相符；但组合仍弱于随机。
   不能因此声称覆盖本身优于随机，独立覆盖的收益尚未由该消融证明。
3. “覆盖项是组合退化的唯一原因”与结果不符。当前应优先检查风险代理及其
   选择分布，而不是继续减小 eta 或把这次消融包装成提升。
4. 最终旧快照 MRR 较低不等价于已算出更大的阶段遗忘；risk 的到达分数、
   BWT 和遗忘量仍需阶段日志。没有这些数据时不填造诊断指标。

就现有四组结果，当前实现与配置的 FAHC 选择没有得到有效性支持，纯 risk
表现为负收益。这个结论不需要以“只有 seed1”为理由回避；它也不证明所有
可能的遗忘感知设计都无效。

## 4. 优先核查的机制及证据边界

静态代码确认：`src/fahc.py` 的风险打分是历史模式实体 CE 增量；候选旧事实
使用当前阶段的历史图，打分不经过 diffusion。探测用当前事实做一步更新；
正式训练则有生成特征、回放和多轮更新。一步风险的排序是否能够预测正式
更新后的历史退化，目前尚无直接测量证据。两者并不要求必须使用完全相同的
路径，但这个代理需要验证预测价值。

另外，探测时 `model.train()` 会更新 BatchNorm 缓冲区，probe 的 eval 损失
变化同时包含权重和这些统计量变化；小批量噪声可能进入风险排序。
`probe_hcp_risks()` 在 finally 中恢复权重、缓冲区、梯度、模式、缓存和 RNG，
所以当前不能把“有探测更新”直接等同于探测污染正式模型。缓冲区是否影响
排序需要单独诊断，不能仅凭此代码确认退化根因。

`diffusion/fahc_selector.py` 对完整 HCP 的事实损失增量取平均，再选时间片；
这可能集中到部分关系/实体或小而噪声大的 HCP。它也不直接优化按快照宏平均
MRR。上述都是待检验解释，不能替代阶段分布与实际退化证据。

此前 random/组合的 CSV 显示 B4096 从未达到上限；但不能把这一统计自动
套用到新 risk。当前没有继续增大 B 的证据，也未严格验证四组逐阶段事实数相等。

## 5. 接下来最省算力的顺序

1. 保留当前四组和随机基线，暂停扩大 eta、k、候选倍数、B 和 KD 网格。
   不需要为这次结论立刻重跑已有基线。
2. 先用已有阶段文件做 CPU 分析：比对四组 config 的 source/data/history
   SHA256；核对阶段完成状态、实际回放量、候选风险分布、零风险比例、
   被选时间片、关系/实体覆盖，以及历史模式 BWT/遗忘。当前原日志无这些
   完整记录，需要从实验服务器保留的 run 目录取得。
3. 同一版本、同一 seed、k35 时，在所有可用候选不超过35的早期阶段，三组
   controlled 方法应选全部可用时间片，最终物化事实也应相同。核对这个
   已有日志能检查的约束；若早期事实或到达分数已明显不一致，先查恢复、
   实际配置和运行条件，再解释为选择差异。
4. 若仍希望继续 FAHC，下一次 GPU 工作应是一项短机制诊断，而非完整网格：
   从相同检查点出发，比较至少两个独立小批量的风险排序稳定性，并测量候选
   风险对正式当前数据更新后旧事实退化的排序预测力。使用训练历史事实和
   验证数据，不以测试结果筛选风险公式。已有 stages.jsonl 本身没有记录
   这一匹配的 old/probe/formal 三套候选损失，不能仅凭它计算该相关性。
5. 若风险预测不可靠，就暂停当前风险优先路线，保留 random，或先重新设计
   代理；若预测可靠但回放无收益，再核查事实分布和实际预算。KD 应与
   random+KD 成对评估，它的提升不能单独证明选择器有效。
